# Release notes format

```markdown
## <version> — <date>

### Breaking changes

- <what breaks, what to do instead>

### Highlights

- <one sentence per major capability>

### Changes

- <user-visible change> ([#123](link))

### Fixes

- <what was wrong, what now happens> ([#124](link))

### Internal

- <optional: dependency bumps, refactors with no user-visible effect>
```

Omit empty sections. Keep one line per entry; put detail behind the pull-request link.
